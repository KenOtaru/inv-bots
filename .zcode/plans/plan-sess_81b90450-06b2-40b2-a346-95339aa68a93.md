## Plan: Monte Carlo Analysis & Prediction Method for Digit Differ

### Context
The current `DigitAnalyzer` in `accurateDiffer3_simple.js` (lines 869-947) uses basic frequency-counting: count digits in a window, pick coldest, Laplace smoothing. No statistical confidence estimation, no bootstrap uncertainty, and critically **no memory of which digits the bot already predicted** (over-trade detection).

### New Method: MonteCarloAnalyzer
Replaces DigitAnalyzer with a 5-layer analysis engine:

**Layer 1 — Multi-window Frequency (weight 0.30):** Count digit frequencies across 4 windows (30, 60, 150, 400 ticks). Short windows capture recent cold digits; long windows provide stable baselines.

**Layer 2 — Bayesian Beta Posterior (weight 0.35):** For each digit, compute Beta(c + α/10, (n−c) + 9α/10) posterior from Dirichlet-multinomial model. Use conservative upper bound: `mean + z × sd`. Digit with lowest upper bound is favored.

**Layer 3 — Bootstrap Resampling (weight 0.20):** Run 500 bootstrap resamples of the digit stream. For each digit, compute the 95th percentile of bootstrap frequency distribution. Digit with lowest 95th-percentile is favored.

**Layer 4 — Absence Streak / Gap Analysis (weight 0.15):** Compute ticks since each digit last appeared + average inter-occurrence gap. Digit with currentGap significantly above avgGap is "cold."

**Layer 5 — Hot-Filter & Over-Trade VETO (hard veto, not weighted):**
- If a digit was predicted by the bot within `cooldownTicks` (15 ticks) → VETOED
- If a digit appeared in last `hotFilterTicks` (5 ticks) of tick stream → penalty
- This prevents the bot from re-predicting the same digit too soon

**Consensus scoring:** Each sub-analysis ranks all 10 digits. Weighted consensus score per digit. Require score ≥ 0.40 AND ≥ 2 sources agreeing.

**Gates:** Entropy, chi-square, probability gap, recent hits (same structure as before but with new diagnostic names).

### Files Modified
All changes in `accurateDiffer3_simple.js`:

1. **CONFIG (lines 140-144):** Replace "Digit Analysis (Simple Heuristic)" with Monte Carlo settings (analysisWindows, dirichletAlpha, betaZScore, bootstrapIterations, hotFilterTicks, cooldownTicks, etc.)

2. **DigitAnalyzer class (lines 869-947):** Delete entirely. Replace with `MonteCarloAnalyzer` class implementing the 5-layer analysis, `recordPrediction()` method for over-trade tracking, and compatible `analyze()`/`rank()` interface.

3. **TradingBot constructor (~line 1298):** `new DigitAnalyzer(cfg)` → `new MonteCarloAnalyzer(cfg)`

4. **_analyzeAndTrade (~line 1505):** After trade execution, call `this.analyzer.recordPrediction(digit, symbol)`

5. **_onTradeOpen (~line 1521):** Update Telegram notification to show new fields (consensus score, agreement sources, bootstrap CI, absence streak, cooldown)

6. **DifferBacktester (line 1631):** Update to use MonteCarloAnalyzer, add `recordPrediction()` calls in walk-forward loop, add new diagnostic counters (gatedBootstrapCI, gatedConsensus, gatedCooldown)

- All risk management, circuit breaker, Kelly sizing, PAT auth, Telegram, WebSocket
- Backtest streak tracking and report formatting
